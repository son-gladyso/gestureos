# GestureOS

[简体中文](README.zh-CN.md) · [English](../../README.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português (Brasil)](README.pt-BR.md)

**손가락 집기, 손 펴기, 주먹 쥐기를 브라우저 파티클 장면과의 상호작용으로 바꿔 보세요.**

GestureOS는 크리에이티브 코딩 개발자와 카메라 기반 상호작용에 관심 있는 사람을 위한 작은 실험 공간입니다. MediaPipe 손 추적과 파티클 VFX를 결합하고 제스처 규칙을 렌더링과 분리하여, 효과와 그 작동 원리를 함께 살펴볼 수 있습니다.

카메라 프레임은 브라우저 안에 머물며 이 프로젝트는 이를 업로드하지 않습니다. 데모는 실행 시 CDN에서 MediaPipe를 불러오므로 처음 실행할 때는 네트워크 연결이 필요합니다.

[로컬에서 실행](#run-locally) · [제스처 시나리오](#what-to-try) · [문제 해결](#troubleshooting) · [개선에 참여](#help-improve-gestureos)

<a id="why-try-it"></a>

## 왜 사용해 볼까요?

손 추적 파이프라인을 처음부터 구축하지 않고도 카메라 기반 상호작용을 탐색할 수 있습니다. GestureOS는 내부를 살펴볼 수 있는 작은 제스처 분류기를 브라우저 파티클 장면에 연결하여, 상호작용을 실험하고 그 바탕이 되는 규칙을 이해하도록 돕습니다.

- 집기, 편 손, 주먹이라는 명확한 세 가지 제스처 상태와 추적 대체 상태를 시험합니다.
- 카메라 및 렌더링 루프와 독립적으로 분류기를 살펴봅니다.
- 카메라 프레임은 브라우저 안에 유지되지만, 실행 시 필요한 라이브러리는 여전히 CDN에서 불러온다는 점을 알아 두세요.

이는 실험적인 브라우저 장면으로, 운영체제를 대체하거나 다른 데스크톱 앱을 제어하는 도구가 아닙니다. 제스처 동작은 카메라 위치, 조명, 손이 얼마나 잘 보이는지에 따라 달라집니다.

<a id="what-to-try"></a>

## 시도할 수 있는 것

| 시나리오 | 살펴볼 내용 | 중요한 이유 |
| --- | --- | --- |
| 편 손에서 주먹으로 바꾸기 | 감지된 상태와 그에 따른 파티클 반응 | 신체 동작을 눈에 보이는 브라우저 반응과 연결합니다. |
| 엄지와 검지를 모으기 | 집기 분류 결과 | 불투명한 명령 체계 대신 작고 명확한 제스처를 탐색합니다. |
| 감지 경계 근처에서 자세 유지하기 | 랜드마크 거리가 변할 때의 상태 변화 | 카메라 거리와 임곗값 선택이 중요한 이유를 이해합니다. |
| 분류기 규칙 바꾸기 | 특정 사례에 집중한 테스트와 실시간 장면 | 렌더링 루프에 섞지 않고 상호작용 동작을 개발합니다. |

분류기는 별도로 학습한 제스처 모델이 아니라 랜드마크 간 거리 임곗값을 사용합니다. 임곗값을 확인할 수 있다는 사실이 서로 다른 사용자, 카메라, 촬영 거리에서도 정확하다는 근거가 되지는 않습니다.

<a id="try-the-interaction"></a>

## 상호작용 체험

[로컬 실행](#run-locally) 절차를 따라 카메라 접근을 허용한 다음, 손 펴기, 주먹 쥐기, 엄지와 검지 집기를 시도하세요. 감지된 상태와 장면에 나타나는 반응을 비교하세요. 추적이 불안정하다면 분류기 결과로 해석하기 전에 조명이나 거리를 바꿔 보세요.

이 README에는 아직 실제 카메라로 녹화한 데모가 포함되어 있지 않습니다. 위 절차로 실제 앱을 살펴볼 수 있지만, 모든 카메라나 브라우저를 검증했다는 뜻은 아닙니다.

<a id="requirements"></a>

## 요구 사항

- Node.js 20+ (프로젝트는 현재 로컬 검증에 Node 24 사용)
- 카메라 접근을 지원하는 최신 브라우저
- HTTPS 또는 `localhost` (카메라 API 요구 사항)

<a id="run-locally"></a>

## 로컬 실행

1. 의존성을 설치합니다.

```bash
npm install
```

2. 로컬 정적 서버로 이 폴더를 제공합니다. 예:

```bash
npx http-server . -p 8080
```

3. `http://localhost:8080`을 열고 이 페이지의 카메라 사용을 허용합니다.

**첫 성공 확인:** 페이지에 카메라 기반 상호작용이 나타나고, 편 손, 주먹, 집기 사이를 전환할 때 상태나 장면에 관찰 가능한 변화가 생기는지 확인합니다. 페이지는 열리지만 추적이 동작하지 않는다면 아래 문제 해결 절차를 사용하세요. 페이지가 로드되었다는 것만으로는 카메라 인수 테스트를 통과한 것이 아닙니다.

정적 서버 명령은 `npx`를 사용하며, `http-server`를 아직 사용할 수 없다면 다운로드할 수 있습니다. 실행 시의 MediaPipe 스크립트와 웹 폰트도 외부 호스트를 사용합니다. 카메라를 로컬에서 처리한다고 해서 처음 실행할 때 완전히 오프라인으로 작동하는 것은 아닙니다.

<a id="quality-commands"></a>

## 품질 검사 명령

- `npm run lint`: ESLint 검사
- `npm run format:check`: Prettier 검사
- `npm test`: 단위 테스트 + 무결성 검사
- `npm run check`: 린트 + 형식 검사 + 테스트

<a id="project-structure"></a>

## 프로젝트 구조

- `index.html`: 앱 셸과 UI 레이아웃
- `styles.css`: 시각 시스템과 애니메이션
- `script.js`: 런타임 루프, 파티클, 제스처, 카메라 수명 주기
- `gesture-config.js`: 변경 불가능한 런타임 상수
- `gesture-helpers.js`: 공유 유틸리티 함수
- `gesture-detector.js`: 순수 제스처 분류 로직
- `gesture-policies.js`: 품질 및 카메라 정책 결정과 오류 매핑
- `tests/run-tests.mjs`: 설정, 헬퍼, 감지기, 정책에 대한 단위 검사
- `scripts/quality-check.mjs`: 엄격한 UTF-8 및 구조 무결성 검사

<a id="troubleshooting"></a>

## 문제 해결

- 카메라가 작동하지 않으면 권한을 확인하고 카메라를 사용하는 다른 앱을 닫으세요.
- 원격 호스트에서 실행한다면 HTTPS를 사용하세요.
- CDN 스크립트를 불러오지 못한다면 `cdn.jsdelivr.net`에 대한 네트워크 접근을 확인하세요.

<a id="common-questions"></a>

### 자주 묻는 질문

**데스크톱이나 다른 앱을 제어할 수 있나요?** 아니요. 상호작용은 이 브라우저 데모 안으로 제한됩니다.

**`index.html`을 직접 열어도 되나요?** 문서에 나온 로컬 서버를 사용하세요. 카메라 API에는 `localhost` 또는 HTTPS와 같은 적절한 보안 컨텍스트가 필요합니다.

**카메라에 가까이 가면 제스처가 바뀌는 이유는 무엇인가요?** 분류는 정규화된 랜드마크 거리와 고정 임곗값을 사용합니다. 카메라 위치, 손의 가시성, 자세가 결과에 영향을 줄 수 있습니다. 이는 테스트할 만한 경계 조건이지, 보편적인 제어 방식이 성립한다는 증거가 아닙니다.

**버그를 보고하려면 카메라 영상을 공유해야 하나요?** 아니요. 먼저 브라우저/OS 버전, 자세, 조명 조건, 예상 상태와 관찰된 상태를 제공하고, 가능하면 합성 랜드마크 테스트를 포함하세요.

<a id="repository-scope"></a>

## 저장소 범위

이 저장소에는 브라우저 소스, 결정론적 제스처 분류 로직, 테스트, 품질 검사가 포함됩니다. 로컬 바이너리, 편집기 상태, 로그, 의존성 폴더, 실험용 임시 페이지는 의도적으로 제외됩니다.

<a id="help-improve-gestureos"></a>

## GestureOS 개선에 참여하기

작고 초점이 분명한 기여를 환영합니다. 분류기의 경계 사례, 더 명확한 카메라 권한 오류, 키보드 접근성, 다른 사람이 상호작용을 재현하도록 돕는 문서가 좋은 출발점입니다.

1. 위의 모듈 안내를 읽고 개선할 동작 하나를 고릅니다.
2. 분류기나 정책을 변경한다면 `tests/run-tests.mjs`에 특정 사례에 집중한 테스트를 추가합니다.
3. `npm run check`를 실행하고 실제로 수행한 브라우저/카메라 검사를 설명합니다.
4. 관찰한 문제, 변경 사항, 남아 있는 한계를 설명하는 풀 리퀘스트를 엽니다.

| 첫 기여 | 시작할 파일 | PR에 포함할 내용 |
| --- | --- | --- |
| 잘못 분류되는 경계 사례 | `gesture-detector.js`, `tests/run-tests.mjs` | 합성 랜드마크와 예상 상태. 규칙을 바꿔야 하는 이유도 설명합니다. |
| 더 명확한 카메라 오류 | `gesture-policies.js`, `script.js` | 실패 조건, 예상 메시지, 정책 회귀 테스트. |
| 더 쉬운 사용 안내 | `index.html`, `README.md` | 재현 가능한 상호작용 또는 설정 단계. 실제 기기 검사와 정적 검토를 구분합니다. |

렌더링을 변경할 때는 분류 로직을 독립적으로 테스트할 수 있게 유지하세요. 카메라 관련 변경에는 해당되는 경우 권한 거부, 카메라 사용 불가, 재시도 동작을 포함하세요.

더 큰 상호작용 변경은 먼저 [issue](https://github.com/son-gladyso/gestureos/issues)를 열어 범위를 논의하세요. 가능하면 합성 테스트 입력을 사용하고, 허락 없이 다른 사람의 카메라 녹화물을 첨부하지 마세요.
