# GestureOS

[简体中文](README.zh-CN.md) · [English](../../README.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru.md) · [繁體中文](README.zh-TW.md)

**将捏合、张手或握拳变成浏览器粒子场景中的交互。**

GestureOS 是一个小型实验性创意编程项目，面向创意编程开发者，以及所有对基于摄像头的交互感兴趣的人。它将 MediaPipe 手部追踪与粒子视觉特效结合起来，并将手势规则与渲染分离，让你既能体验效果，也能探索其工作原理。

摄像头画面保留在浏览器内，本项目不会上传这些画面。演示在运行时通过 CDN 加载 MediaPipe，因此首次启动需要网络连接。

[本地试用](#run-locally) · [手势场景](#what-to-try) · [故障排查](#troubleshooting) · [参与改进](#help-improve-gestureos)

<a id="why-try-it"></a>

## 为什么值得一试？

无需从头搭建手部追踪流程，即可探索基于摄像头的交互。GestureOS 将一个小型、可检查的手势分类器连接到浏览器粒子场景，让你在尝试交互的同时理解背后的规则。

- 尝试三种明确的手势状态：捏合、张手和握拳，并提供追踪回退状态。
- 独立于摄像头和渲染循环检查分类器。
- 摄像头画面保留在你的浏览器中，但请注意，运行时库仍通过 CDN 加载。

这是一个实验性浏览器场景，不是操作系统替代品，也不是控制其他桌面应用的工具。手势行为取决于摄像头位置、光照以及手部的可见程度。

<a id="what-to-try"></a>

## 可以尝试什么

| 场景 | 观察内容 | 意义 |
| --- | --- | --- |
| 从张手变为握拳 | 检测到的状态及对应的粒子响应 | 将身体动作与可见的浏览器响应联系起来。 |
| 将拇指与食指靠拢 | 捏合分类结果 | 探索一种简单、明确的手势，而不是不透明的命令集合。 |
| 在检测边界附近保持一个姿势 | 关键点距离变化时的状态变化 | 理解摄像头距离和阈值选择的重要性。 |
| 修改一条分类器规则 | 有针对性的测试和实时场景 | 开发交互行为，而不将其混入渲染循环。 |

分类器使用关键点距离阈值，而不是经过训练的自定义手势模型。虽然阈值可以检查，但这并不能证明它在不同用户、摄像头或观察距离下都具有准确性。

<a id="try-the-interaction"></a>

## 体验交互

按照[本地运行](#run-locally)操作，允许摄像头访问，然后尝试张手、握拳和拇指与食指捏合。对照检测到的状态与场景中的可见响应。如果追踪不稳定，请先调整光照或距离，再判断是否属于分类器问题。

此 README 暂未包含真实摄像头演示录像。上述步骤可让你检查实际应用，但不代表每种摄像头或浏览器都已经过验证。

<a id="requirements"></a>

## 环境要求

- Node.js 20+（项目目前使用 Node 24 进行本地验证）
- 支持摄像头访问的现代浏览器
- HTTPS 或 `localhost`（摄像头 API 要求）

<a id="run-locally"></a>

## 本地运行

1. 安装依赖：

```bash
npm install
```

2. 使用本地静态服务器提供此文件夹。例如：

```bash
npx http-server . -p 8080
```

3. 打开 `http://localhost:8080`，并允许此页面使用摄像头。

**首次成功检查的标准：**页面显示由摄像头驱动的交互，在张手、握拳和捏合之间切换时，能够观察到状态或场景变化。如果页面已加载但追踪未工作，请使用下面的故障排查步骤；仅仅加载页面并不算通过摄像头验收测试。

静态服务器命令使用 `npx`，如果尚未安装 `http-server`，可能会下载它。运行时 MediaPipe 脚本和网页字体也使用外部主机；在本地处理摄像头画面不意味着首次启动完全离线。

<a id="quality-commands"></a>

## 质量检查命令

- `npm run lint`：ESLint 检查
- `npm run format:check`：Prettier 检查
- `npm test`：单元测试 + 完整性检查
- `npm run check`：代码检查 + 格式检查 + 测试

<a id="project-structure"></a>

## 项目结构

- `index.html`：应用外壳与 UI 布局
- `styles.css`：视觉系统与动画
- `script.js`：运行时循环、粒子、手势与摄像头生命周期
- `gesture-config.js`：不可变的运行时常量
- `gesture-helpers.js`：共享工具函数
- `gesture-detector.js`：纯手势分类逻辑
- `gesture-policies.js`：质量与摄像头策略决策及错误映射
- `tests/run-tests.mjs`：配置、工具函数、检测器与策略的单元检查
- `scripts/quality-check.mjs`：严格 UTF-8 与结构完整性检查

<a id="troubleshooting"></a>

## 故障排查

- 如果摄像头无法工作，请检查权限并关闭其他使用摄像头的应用。
- 如果运行在远程主机上，请使用 HTTPS。
- 如果 CDN 脚本加载失败，请检查是否能访问 `cdn.jsdelivr.net`。

<a id="common-questions"></a>

### 常见问题

**它能控制我的桌面或其他应用吗？**不能。交互仅限于此浏览器演示。

**可以直接打开 `index.html` 吗？**请使用文档中的本地服务器。摄像头 API 需要合适的安全上下文，例如 `localhost` 或 HTTPS。

**为什么靠近摄像头后手势会改变？**分类使用归一化的关键点距离与固定阈值。摄像头位置、手部可见程度和姿势都可能影响结果；这是值得测试的边界条件，而不是通用控制方案已经成立的证据。

**报告问题时需要分享摄像头视频吗？**不需要。请先提供浏览器和操作系统版本、姿势、光照条件、预期与观察到的状态，并尽可能提供合成关键点测试。

<a id="repository-scope"></a>

## 仓库范围

此仓库包含浏览器源代码、确定性手势分类逻辑、测试与质量检查。本地二进制文件、编辑器状态、日志、依赖文件夹及实验性临时页面均有意排除在外。

<a id="help-improve-gestureos"></a>

## 帮助改进 GestureOS

欢迎小而集中的贡献。适合入手的方向包括分类器边界情况、更清晰的摄像头权限错误提示、键盘无障碍支持，以及帮助他人复现交互的文档。

1. 阅读上方的模块说明，选择一种行为进行改进。
2. 如果修改分类器或策略，请在 `tests/run-tests.mjs` 中添加有针对性的用例。
3. 运行 `npm run check`，并说明你实际执行了哪些浏览器或摄像头检查。
4. 发起拉取请求，说明观察到的问题、修改内容与仍然存在的限制。

| 首次贡献方向 | 从这里开始 | PR 中应包含的内容 |
| --- | --- | --- |
| 被错误分类的边界情况 | `gesture-detector.js`、`tests/run-tests.mjs` | 合成关键点与预期状态；解释为什么需要修改规则。 |
| 更清晰的摄像头故障提示 | `gesture-policies.js`、`script.js` | 故障条件、预期消息与策略回归测试。 |
| 更易用的说明 | `index.html`、`README.md` | 可复现的交互或设置步骤；区分实际设备检查与静态审阅。 |

修改渲染时，请保持分类逻辑可独立测试。修改摄像头相关功能时，请在适用情况下覆盖拒绝权限、摄像头不可用及重试行为。

较大的交互改动请先提交 [issue](https://github.com/son-gladyso/gestureos/issues) 讨论范围。尽可能使用合成测试输入；未经许可，不要附上他人的摄像头录像。
