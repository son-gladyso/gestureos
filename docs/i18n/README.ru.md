# GestureOS

[简体中文](README.zh-CN.md) · [English](../../README.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru.md) · [繁體中文](README.zh-TW.md)

**Превратите щипок пальцами, открытую ладонь или кулак во взаимодействие со сценой частиц в браузере.**

GestureOS — небольшая экспериментальная площадка для разработчиков творческих интерактивных проектов и всех, кому интересно взаимодействие с помощью камеры. Она объединяет отслеживание рук MediaPipe с визуальными эффектами частиц и отделяет правила жестов от отрисовки, позволяя изучать и эффект, и его устройство.

Кадры камеры остаются в браузере: проект их не загружает на сервер. Во время работы демонстрация использует MediaPipe из CDN, поэтому первый запуск требует доступа к сети.

[Попробовать локально](#run-locally) · [Сценарии жестов](#what-to-try) · [Устранение неполадок](#troubleshooting) · [Участие в разработке](#help-improve-gestureos)

<a id="why-try-it"></a>

## Зачем пробовать?

Изучайте взаимодействие с камерой, не создавая систему отслеживания рук с нуля. GestureOS связывает небольшой, доступный для проверки классификатор жестов со сценой частиц в браузере: можно экспериментировать с поведением и понимать стоящие за ним правила.

- Попробуйте три явно заданных состояния: щипок, открытую ладонь и кулак, а также резервное состояние отслеживания.
- Изучайте классификатор независимо от камеры и цикла отрисовки.
- Сохраняйте кадры камеры в браузере, учитывая, что библиотеки времени выполнения всё же загружаются из CDN.

Это экспериментальная браузерная сцена, а не замена операционной системы и не средство управления другими настольными приложениями. Поведение жестов зависит от положения камеры, освещения и видимости руки.

<a id="what-to-try"></a>

## Что попробовать

| Сценарий | Что изучать | Зачем это нужно |
| --- | --- | --- |
| Перейти от открытой ладони к кулаку | Распознанное состояние и соответствующую реакцию частиц | Связать физическое действие с видимым ответом браузера. |
| Свести большой и указательный пальцы | Классификацию щипка | Изучить небольшой явно заданный жест вместо непрозрачного набора команд. |
| Удерживать позу около границы распознавания | Изменения состояния при изменении расстояний между ключевыми точками | Понять значение расстояния до камеры и выбора порогов. |
| Изменить правило классификатора | Узкий тест и живую сцену | Развивать поведение взаимодействия, не смешивая его с циклом отрисовки. |

Классификатор использует пороги расстояний между ключевыми точками, а не специально обученную модель жестов. Пороги можно проверить, но это не доказывает точность для разных пользователей, камер или расстояний съёмки.

<a id="try-the-interaction"></a>

## Попробуйте взаимодействие

Выполните [локальный запуск](#run-locally), разрешите доступ к камере и попробуйте открытую ладонь, кулак и щипок большим и указательным пальцами. Сравните распознанное состояние с видимой реакцией сцены. Если отслеживание нестабильно, сначала измените освещение или расстояние, прежде чем считать это результатом работы классификатора.

Записанной демонстрации с реальной камерой в этом README пока нет. Эти шаги позволяют проверить само приложение, но не означают, что проверены все камеры и браузеры.

<a id="requirements"></a>

## Требования

- Node.js 20+ (для локальной проверки проект сейчас использует Node 24)
- Современный браузер с доступом к камере
- HTTPS или `localhost` (требование API камеры)

<a id="run-locally"></a>

## Локальный запуск

1. Установите зависимости:

```bash
npm install
```

2. Раздайте эту папку локальным сервером статических файлов. Например:

```bash
npx http-server . -p 8080
```

3. Откройте `http://localhost:8080` и разрешите странице использовать камеру.

**Первая успешная проверка:** страница показывает взаимодействие, управляемое камерой, а переходы между открытой ладонью, кулаком и щипком вызывают наблюдаемые изменения состояния или сцены. Если страница загрузилась, но отслеживание не работает, воспользуйтесь разделом устранения неполадок: сама загрузка страницы не является приёмочным тестом камеры.

Команда статического сервера использует `npx` и может скачать `http-server`, если его ещё нет. Скрипты MediaPipe времени выполнения и веб-шрифты также используют внешние хосты; локальная обработка камеры не означает полностью автономный первый запуск.

<a id="quality-commands"></a>

## Команды проверки качества

- `npm run lint`: проверки ESLint
- `npm run format:check`: проверка Prettier
- `npm test`: модульные тесты + проверки целостности
- `npm run check`: lint + форматирование + тесты

<a id="project-structure"></a>

## Структура проекта

- `index.html`: оболочка приложения и разметка интерфейса
- `styles.css`: визуальная система и анимации
- `script.js`: рабочий цикл, частицы, жесты, жизненный цикл камеры
- `gesture-config.js`: неизменяемые константы времени выполнения
- `gesture-helpers.js`: общие вспомогательные функции
- `gesture-detector.js`: чистая логика классификации жестов
- `gesture-policies.js`: решения политик качества/камеры и сопоставление ошибок
- `tests/run-tests.mjs`: модульные проверки конфигурации, вспомогательных функций, детектора и политик
- `scripts/quality-check.mjs`: строгие проверки UTF-8 и структурной целостности

<a id="troubleshooting"></a>

## Устранение неполадок

- При сбое камеры проверьте разрешения и закройте другие приложения, использующие камеру.
- При запуске на удалённом хосте используйте HTTPS.
- Если скрипты CDN не загружаются, проверьте сетевой доступ к `cdn.jsdelivr.net`.

<a id="common-questions"></a>

### Частые вопросы

**Можно управлять рабочим столом или другими приложениями?** Нет. Взаимодействие ограничено этой браузерной демонстрацией.

**Можно открыть `index.html` напрямую?** Используйте описанный локальный сервер. API камеры требуют подходящего безопасного контекста, например `localhost` или HTTPS.

**Почему жест меняется, когда я приближаюсь?** Классификация использует нормализованные расстояния между ключевыми точками и фиксированные пороги. Положение камеры, видимость руки и поза могут влиять на результат; это полезная граница для тестирования, а не доказательство универсальной схемы управления.

**Для сообщения об ошибке нужно делиться видео с камеры?** Нет. Начните с версий браузера/ОС, позы, освещения, ожидаемого и наблюдаемого состояния, а по возможности добавьте тест с синтетическими ключевыми точками.

<a id="repository-scope"></a>

## Содержимое репозитория

Репозиторий содержит браузерный исходный код, детерминированную классификацию жестов, тесты и проверки качества. Локальные бинарные файлы, состояние редактора, журналы, папки зависимостей и экспериментальные временные страницы намеренно исключены.

<a id="help-improve-gestureos"></a>

## Помогите улучшить GestureOS

Небольшие, узко направленные изменения приветствуются. Полезные начальные задачи: пограничные случаи классификатора, более понятные ошибки разрешения камеры, доступность с клавиатуры и документация, помогающая воспроизвести взаимодействие.

1. Прочитайте карту модулей выше и выберите одно поведение для улучшения.
2. При изменении классификатора или политик добавьте узкий тест в `tests/run-tests.mjs`.
3. Запустите `npm run check` и укажите, какие проверки браузера/камеры вы действительно выполнили.
4. Откройте pull request с описанием наблюдаемой проблемы, изменения и оставшихся ограничений.

| Первый вклад | С чего начать | Что приложить к PR |
| --- | --- | --- |
| Ошибочно классифицированный пограничный случай | `gesture-detector.js`, `tests/run-tests.mjs` | Синтетические точки и ожидаемое состояние; объяснение необходимости изменения правила. |
| Более понятный сбой камеры | `gesture-policies.js`, `script.js` | Условия сбоя, ожидаемое сообщение и регрессионный тест политики. |
| Более удобные инструкции | `index.html`, `README.md` | Воспроизводимый шаг взаимодействия или настройки; отделяйте проверки устройства от статического анализа. |

При изменении отрисовки сохраняйте независимую тестируемость классификации. Для изменений камеры при необходимости учитывайте отказ в разрешении, недоступную камеру и повторную попытку.

Для крупных изменений взаимодействия сначала откройте [issue](https://github.com/son-gladyso/gestureos/issues), чтобы обсудить объём. По возможности используйте синтетические входные данные; не прикладывайте запись камеры другого человека без его разрешения.
