# GestureOS

[简体中文](README.zh-CN.md) · [English](../../README.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru.md) · [繁體中文](README.zh-TW.md)

**將捏合、張手或握拳變成瀏覽器粒子場景中的互動。**

GestureOS 是一個小型實驗性創意程式設計專案，面向創意程式開發者，以及所有對攝影機互動感興趣的人。它結合 MediaPipe 手部追蹤與粒子視覺特效，並將手勢規則與渲染分離，讓你既能體驗效果，也能探索其運作原理。

攝影機畫面保留在瀏覽器內，本專案不會上傳這些畫面。示範在執行時透過 CDN 載入 MediaPipe，因此首次啟動需要網路連線。

[本機試用](#run-locally) · [手勢場景](#what-to-try) · [疑難排解](#troubleshooting) · [參與改進](#help-improve-gestureos)

<a id="why-try-it"></a>

## 為什麼值得一試？

不必從頭建置手部追蹤流程，即可探索攝影機互動。GestureOS 將小型、可檢視的手勢分類器連接至瀏覽器粒子場景，讓你在嘗試互動的同時理解背後的規則。

- 嘗試三種明確的手勢狀態：捏合、張手和握拳，另有追蹤備援狀態。
- 不依賴攝影機與渲染迴圈，即可獨立檢查分類器。
- 攝影機畫面留在你的瀏覽器中，但執行時函式庫仍透過 CDN 載入。

這是實驗性瀏覽器場景，不是替代作業系統，也不是控制其他桌面應用程式的工具。手勢行為取決於攝影機位置、光線，以及手部是否清楚可見。

<a id="what-to-try"></a>

## 可以嘗試什麼

| 場景 | 觀察內容 | 意義 |
| --- | --- | --- |
| 從張手變為握拳 | 偵測到的狀態及相應粒子反應 | 將身體動作與可見的瀏覽器反應連結起來。 |
| 將拇指與食指靠攏 | 捏合分類結果 | 探索簡單、明確的手勢，而非不透明的指令集合。 |
| 在偵測邊界附近保持姿勢 | 關鍵點距離改變時的狀態變化 | 理解攝影機距離與門檻選擇為何重要。 |
| 修改一條分類器規則 | 針對性測試與即時場景 | 開發互動行為，而不將其混入渲染迴圈。 |

分類器使用關鍵點距離門檻，而不是經過訓練的自訂手勢模型。雖然門檻可供檢查，但不代表它在不同使用者、攝影機或觀看距離下都準確。

<a id="try-the-interaction"></a>

## 體驗互動

依照[本機執行](#run-locally)操作，允許攝影機存取，然後嘗試張手、握拳及拇指與食指捏合。比較偵測狀態與場景中的可見反應。如果追蹤不穩定，請先調整光線或距離，再判斷是否屬於分類器問題。

此 README 尚未包含真實攝影機示範錄影。上述步驟可讓你檢查實際應用程式，但不代表每一種攝影機或瀏覽器都已驗證。

<a id="requirements"></a>

## 環境需求

- Node.js 20+（專案目前使用 Node 24 進行本機驗證）
- 支援攝影機存取的現代瀏覽器
- HTTPS 或 `localhost`（攝影機 API 的要求）

<a id="run-locally"></a>

## 本機執行

1. 安裝相依套件：

```bash
npm install
```

2. 使用本機靜態伺服器提供此資料夾。例如：

```bash
npx http-server . -p 8080
```

3. 開啟 `http://localhost:8080`，並允許此頁面使用攝影機。

**首次成功檢查的標準：**頁面呈現由攝影機驅動的互動，在張手、握拳和捏合之間切換時，可觀察到狀態或場景變化。如果頁面已載入但追蹤未運作，請使用下方疑難排解步驟；僅載入頁面不算通過攝影機驗收測試。

靜態伺服器指令使用 `npx`；若尚未提供 `http-server`，可能會下載它。執行時的 MediaPipe 指令碼及網頁字型也使用外部主機。本機處理攝影機畫面不代表首次啟動完全離線。

<a id="quality-commands"></a>

## 品質檢查指令

- `npm run lint`：ESLint 檢查
- `npm run format:check`：Prettier 檢查
- `npm test`：單元測試 + 完整性檢查
- `npm run check`：程式碼檢查 + 格式檢查 + 測試

<a id="project-structure"></a>

## 專案結構

- `index.html`：應用程式框架與 UI 版面配置
- `styles.css`：視覺系統與動畫
- `script.js`：執行迴圈、粒子、手勢與攝影機生命週期
- `gesture-config.js`：不可變的執行常數
- `gesture-helpers.js`：共用工具函式
- `gesture-detector.js`：純手勢分類邏輯
- `gesture-policies.js`：品質／攝影機策略決策與錯誤對應
- `tests/run-tests.mjs`：設定、工具函式、偵測器與策略的單元檢查
- `scripts/quality-check.mjs`：嚴格 UTF-8 與結構完整性檢查

<a id="troubleshooting"></a>

## 疑難排解

- 攝影機無法運作時，請檢查權限，並關閉其他使用攝影機的應用程式。
- 若在遠端主機執行，請使用 HTTPS。
- 若 CDN 指令碼載入失敗，請檢查能否連線至 `cdn.jsdelivr.net`。

<a id="common-questions"></a>

### 常見問題

**它能控制我的桌面或其他應用程式嗎？**不能。互動僅限於此瀏覽器示範。

**可以直接開啟 `index.html` 嗎？**請改用文件所述的本機伺服器。攝影機 API 需要適當的安全環境，例如 `localhost` 或 HTTPS。

**為什麼靠近攝影機後手勢會改變？**分類使用正規化的關鍵點距離與固定門檻。攝影機位置、手部可見程度及姿勢都可能影響結果；這是值得測試的邊界條件，不是通用控制方案已成立的證據。

**回報問題時需要分享攝影機影片嗎？**不需要。請先提供瀏覽器／作業系統版本、姿勢、光線條件、預期與觀察到的狀態，並盡可能提供合成關鍵點測試。

## 儲存庫範圍

<a id="help-improve-gestureos"></a>

## 協助改進 GestureOS

歡迎小而聚焦的貢獻。適合入手的方向包括分類器邊界案例、更清楚的攝影機權限錯誤提示、鍵盤無障礙支援，以及幫助他人重現互動的文件。

1. 閱讀上方模組說明，選擇一種行為改進。
2. 修改分類器或策略時，在 `tests/run-tests.mjs` 加入針對性案例。
3. 執行 `npm run check`，並說明實際做過哪些瀏覽器／攝影機檢查。
4. 提出拉取請求，說明觀察到的問題、修改內容與仍存在的限制。

| 首次貢獻方向 | 從這裡開始 | PR 應包含的內容 |
| --- | --- | --- |
| 分類錯誤的邊界案例 | `gesture-detector.js`、`tests/run-tests.mjs` | 合成關鍵點與預期狀態；解釋為何需要修改規則。 |
| 更清楚的攝影機故障提示 | `gesture-policies.js`、`script.js` | 故障條件、預期訊息與策略回歸測試。 |
| 更容易使用的說明 | `index.html`、`README.md` | 可重現的互動或設定步驟；區分實際裝置檢查與靜態審閱。 |

修改渲染時，請保持分類邏輯可獨立測試。修改攝影機相關功能時，依情況涵蓋拒絕權限、攝影機不可用及重試行為。

較大的互動變更請先提出 [issue](https://github.com/son-gladyso/gestureos/issues) 討論範圍。盡可能使用合成測試輸入；未經許可，不要附上他人的攝影機錄影。
