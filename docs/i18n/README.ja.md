# GestureOS

[简体中文](README.zh-CN.md) · [English](../../README.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português (Brasil)](README.pt-BR.md)

**指をつまむ、手を開く、こぶしを握る。そんな動きをブラウザーのパーティクルシーンとのインタラクションに。**

GestureOS は、クリエイティブコーディングの開発者や、カメラを使ったインタラクションに関心のある方のための、小さな実験用プレイグラウンドです。MediaPipe のハンドトラッキングとパーティクル VFX を組み合わせ、ジェスチャーのルールを描画処理から切り離しているため、エフェクトとその仕組みの両方を調べられます。

カメラのフレームはブラウザー内に留まり、このプロジェクトによってアップロードされることはありません。デモは実行時に CDN から MediaPipe を読み込むため、初回起動にはネットワーク接続が必要です。

[ローカルで試す](#run-locally) · [ジェスチャーのシナリオ](#what-to-try) · [トラブルシューティング](#troubleshooting) · [改良に参加する](#help-improve-gestureos)

<a id="why-try-it"></a>

## 試す理由

ハンドトラッキングのパイプラインを一から作らずに、カメラを使ったインタラクションを探れます。GestureOS は、小さく中身を確認できるジェスチャー分類器をブラウザーのパーティクルシーンにつなぎ、操作を試しながら、その背後にあるルールを理解できるようにします。

- ピンチ、開いた手、こぶしという明確な 3 種類のジェスチャー状態と、トラッキングのフォールバックを試せます。
- カメラや描画ループから独立して分類器を確認できます。
- カメラのフレームはブラウザー内に留まりますが、実行時のライブラリは引き続き CDN から読み込まれる点に注意してください。

これは実験的なブラウザーシーンであり、OS の代替でも、他のデスクトップアプリを操作するツールでもありません。ジェスチャーの挙動は、カメラの配置、照明、手の見え方によって変わります。

<a id="what-to-try"></a>

## 試してみること

| シナリオ | 確認する点 | 意義 |
| --- | --- | --- |
| 開いた手からこぶしに変える | 検出状態と、それに対応するパーティクルの反応 | 身体の動作をブラウザーの目に見える反応につなげます。 |
| 親指と人差し指を近づける | ピンチの分類 | 不透明なコマンド体系ではなく、小さく明確なジェスチャーを探れます。 |
| 検出境界付近でポーズを保つ | ランドマーク間の距離に応じた状態変化 | カメラとの距離やしきい値の選択が重要な理由を理解できます。 |
| 分類器のルールを変更する | 対象を絞ったテストとライブシーン | 描画ループに混ぜずにインタラクションの挙動を開発できます。 |

分類器は、独自に学習したジェスチャーモデルではなく、ランドマーク間の距離のしきい値を使います。しきい値を確認できるからといって、ユーザー、カメラ、撮影距離が異なる条件での精度が保証されるわけではありません。

<a id="try-the-interaction"></a>

## インタラクションを試す

[ローカル実行](#run-locally)に従ってカメラへのアクセスを許可し、開いた手、こぶし、親指と人差し指のピンチを試してください。検出された状態と、画面上のシーンの反応を比べます。トラッキングが不安定な場合は、分類器の結果と判断する前に、照明や距離を変えてください。

この README には、実際のカメラを使ったデモ録画はまだありません。上記の手順で実際のアプリを確認できますが、すべてのカメラやブラウザーで検証済みだと主張するものではありません。

<a id="requirements"></a>

## 必要な環境

- Node.js 20+（現在、プロジェクトのローカル検証には Node 24 を使用）
- カメラにアクセスできる最新のブラウザー
- HTTPS または `localhost`（カメラ API の要件）

<a id="run-locally"></a>

## ローカル実行

1. 依存関係をインストールします。

```bash
npm install
```

2. ローカルの静的サーバーでこのフォルダーを配信します。例：

```bash
npx http-server . -p 8080
```

3. `http://localhost:8080` を開き、このページによるカメラの使用を許可します。

**最初の成功確認：**ページにカメラを使ったインタラクションが表示され、開いた手、こぶし、ピンチを切り替えると、状態やシーンに目に見える変化が起きることを確認します。ページは読み込まれるのにトラッキングが動かない場合は、以下のトラブルシューティングを参照してください。ページが読み込まれただけでは、カメラの受け入れテストになりません。

静的サーバーのコマンドは `npx` を使うため、`http-server` がまだ利用できない場合にはダウンロードすることがあります。実行時の MediaPipe スクリプトと Web フォントも外部ホストを使用します。カメラ処理がローカルで行われることは、初回起動が完全にオフラインであることを意味しません。

<a id="quality-commands"></a>

## 品質確認コマンド

- `npm run lint`：ESLint によるチェック
- `npm run format:check`：Prettier によるチェック
- `npm test`：単体テスト + 整合性チェック
- `npm run check`：リント + フォーマット確認 + テスト

<a id="project-structure"></a>

## プロジェクト構成

- `index.html`：アプリのシェルと UI レイアウト
- `styles.css`：ビジュアルシステムとアニメーション
- `script.js`：実行ループ、パーティクル、ジェスチャー、カメラのライフサイクル
- `gesture-config.js`：変更不可の実行時定数
- `gesture-helpers.js`：共通のユーティリティ関数
- `gesture-detector.js`：純粋なジェスチャー分類ロジック
- `gesture-policies.js`：品質・カメラのポリシー判断とエラーマッピング
- `tests/run-tests.mjs`：設定、ヘルパー、検出器、ポリシーの単体チェック
- `scripts/quality-check.mjs`：厳密な UTF-8 と構造的整合性のチェック

<a id="troubleshooting"></a>

## トラブルシューティング

- カメラが動かない場合は、権限を確認し、カメラを使用している他のアプリを閉じてください。
- リモートホストで実行する場合は、HTTPS を使用してください。
- CDN のスクリプトが読み込まれない場合は、`cdn.jsdelivr.net` へのネットワーク接続を確認してください。

<a id="common-questions"></a>

### よくある質問

**デスクトップや他のアプリを操作できますか？** いいえ。インタラクションはこのブラウザーデモ内に限定されます。

**`index.html` を直接開いてもよいですか？** 記載されているローカルサーバーを使ってください。カメラ API には、`localhost` や HTTPS などの適切なセキュアコンテキストが必要です。

**カメラに近づくとジェスチャーが変わるのはなぜですか？** 分類は正規化したランドマーク間の距離と固定しきい値を使用します。カメラの位置、手の見え方、ポーズが結果に影響する場合があります。これはテストに適した境界条件であり、汎用的な操作方式を示す証拠ではありません。

**バグ報告にカメラ映像を共有する必要がありますか？** ありません。まずはブラウザーと OS のバージョン、ポーズ、照明条件、期待した状態と観察した状態、可能であれば合成ランドマークによるテストを提供してください。

<a id="repository-scope"></a>

## リポジトリの範囲

このリポジトリには、ブラウザー向けソース、決定論的なジェスチャー分類ロジック、テスト、品質チェックを含みます。ローカルのバイナリ、エディターの状態、ログ、依存関係フォルダー、実験用の一時ページは意図的に除外しています。

<a id="help-improve-gestureos"></a>

## GestureOS の改良に協力する

小さく焦点を絞った貢献を歓迎します。分類器の境界ケース、わかりやすいカメラ権限エラー、キーボードアクセシビリティ、インタラクションを再現しやすくするドキュメントなどが、よい出発点です。

1. 上記のモジュール構成を読み、改良する挙動を 1 つ選びます。
2. 分類器やポリシーを変更する場合は、`tests/run-tests.mjs` に対象を絞ったケースを追加します。
3. `npm run check` を実行し、実際に行ったブラウザー・カメラの確認を記載します。
4. 観察した問題、変更内容、残る制約を説明するプルリクエストを作成します。

| 最初の貢献 | 開始するファイル | PR に含める内容 |
| --- | --- | --- |
| 誤分類される境界ケース | `gesture-detector.js`、`tests/run-tests.mjs` | 合成ランドマークと期待する状態。ルールを変えるべき理由も説明します。 |
| より明確なカメラエラー | `gesture-policies.js`、`script.js` | 失敗条件、期待するメッセージ、ポリシーの回帰テスト。 |
| 使いやすい手順 | `index.html`、`README.md` | 再現可能なインタラクションまたはセットアップ手順。実機確認と静的なレビューを区別します。 |

描画を変更する際は、分類ロジックを独立してテストできる状態に保ってください。カメラに関する変更では、必要に応じて権限拒否、カメラが利用できない場合、再試行の挙動を含めてください。

大きなインタラクション変更は、まず [issue](https://github.com/son-gladyso/gestureos/issues) を作成して範囲を相談してください。可能な限り合成テスト入力を使用し、他人のカメラ録画を許可なく添付しないでください。
